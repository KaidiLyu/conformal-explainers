## 2. 用什么衡量“复现效果”

论文来源：[Learning Conformal Explainers for Image Classifiers](https://arxiv.org/html/2509.21209v1)，重点参考第 4 节、表 1–5、图 4/6。

Imagenette 上 FastSHAP 的几个对照锚点如下（目标置信度 95%）：

| 校准方式 | 论文平均保留面积 | 论文 fidelity |
|---|---:|---:|
| Super-Pixels | 36.7% | 96.0% |
| Scaled Values | 33.7% | 96.5% |
| Pixelwise | 37.4% | 84.8% |

这些数据来自论文表 1、2，供比较，不是对我们的结果作出的保证。Pixelwise 的论文结果本身低于目标，不能用“所有方法必须达到 95%”作为验收规则。保留全图也可能得到 100% fidelity，必须同时检查面积和全图回退比例。

验收分三层：

1. **流程正确**：固定四路划分；训练/调参仅用训练与验证数据；校准求阈值；测试使用冻结阈值。样本数与指纹可审查。
2. **结果可比较**：完成全部主配置，报告 fidelity、Wilson 区间、保留面积的均值/标准差、原图准确率、回退比例和明确口径的耗时。生成论文值/本项目值/差值对照表。
3. **结论有证据**：检验 FastSHAP 的面积优势、超像素方法的表现和置信度变化趋势是否出现；不一致时报告差距及可验证原因。不能挑选有利图片或在最终测试集上调参去追逐论文数值。

不预先承诺数字完全一致。作者的样本身份、训练细节和完整 FastSHAP 架构信息不足；我们的独立划分与明确记录的实现选择都会影响结果。若需规定数值容差，应在最终测试前制定，并解释依据；单个置信区间重叠不足以证明完全复现。

上述规则来自课程通知，本计划尚未登录门户验证权限、队列、GPU 请求语法、存储策略或具体计费方式。提交脚本前应阅读课程接入说明，不能猜测分区名称或 Slurm GPU 参数。也不能直接假设四个人的额度可合并使用。

先完成同一小任务的吞吐与显存测量，再选 L4/A100 和 batch size。只在 CPU 的数据准备、报告绘图等阶段不占用交互式 GPU 会话；按照集群支持的作业方式安排。KernelSHAP 的 CPU 拟合和逐图 SLIC 可能造成低 GPU 利用率，需在试跑时观察并通过预计算/批处理改进，不能靠空转维持节点。

训练目标为每 5–10 分钟或每个较短 epoch 保存一次可恢复状态，取更频繁者；保存模型、优化器、epoch/step、随机状态及数据顺序。评估按图或短批次保存进度。checkpoint 写入课程允许的持久存储，并采用临时文件后原子替换，避免中断留下损坏文件。

初始 GPU 预算是规划上限，不是测速结论：

| 用途 | 暂定 GPU 小时上限 |
|---|---:|
| 环境、显存、吞吐与恢复试跑 | 2 |
| 分类器开发与正式训练 | 16 |
| FastSHAP 开发与正式训练 | 32 |
| 一轮完整主实验 | 70 |
| 预先规定的重复/敏感性实验 | 30 |
| 合计 | 150 |

另留 50 小时故障与重跑缓冲，总规划不超过单人 300 小时额度。每阶段达上限前先检查日志和剩余额度，不自动追加大批量作业。若首轮测速发现预算不足，调整主实验启动计划，并明确记录任何范围变化。

完整校准在未去重候选的情况下最多约需 `2924 × 5 × 3 × 101 = 4,429,860` 次单图掩码分类前向，此外还有归因计算；实际批次数和去重后的候选数不同。这解释了为什么 KernelSHAP、校准搜索和断点恢复比继续装饰界面更优先。

测速使用训练/验证数据划出的开发子集，建议先测每方法 10–20 张图，记录归因、分割和候选搜索耗时。按正式样本数外推并留余量，不能用 16×16 合成图片的计时估计 224×224 ResNet50 成本。
